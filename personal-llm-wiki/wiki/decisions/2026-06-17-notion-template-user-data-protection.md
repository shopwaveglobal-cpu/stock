## 배경

구독 상품은 주기적으로 데이터를 갱신해야 하는데, 고객의 매매 기록·메모가 같은 데이터베이스에 있음.

## 결정과 근거

1. **필드 소유권 분리**: 공급자 관리 필드 / 사용자 관리 필드를 스키마 수준에서 구분. 업데이트 파일에는 공급자 필드만
2. **고유키는 종목코드**: 종목명은 변경되므로 병합 기준으로 불안정
3. **삭제 금지**: 상장폐지도 삭제 대신 상태 표시 — 해당 행에 고객 기록이 남아 있을 수 있음
4. **1차는 CSV 수동 병합**: 노션 import만으로 사용자 데이터를 안전하게 지키는 가장 현실적인 방식. API 자동화는 2차

## 재검토 조건

- 2차(Notion API 자동 업데이트) 착수 시 — 같은 원칙(공급자 필드만 수정, 삭제 금지)을 API 도구에 그대로 적용
