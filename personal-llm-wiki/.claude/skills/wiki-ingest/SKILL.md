# wiki-ingest

새 자료 1개를 raw/에서 wiki/로 인입하는 절차. **한 번에 1개 파일만** 처리한다.

## 사전 조건

- 대상 파일이 raw/inbox/ 또는 raw/samples/ 안에 있어야 한다.
- 대상에 API 키·토큰·비밀번호·회사 기밀이 보이면 즉시 중단하고 사용자에게 보고한다.
- raw/ 파일은 읽기만 한다. 이동·수정·삭제 금지.

## 절차

### 1. 원본 읽기
- 파일 전체를 읽는다. 유형(스펙/테스트/오류/결정/조사)과 날짜를 파악한다.
- 날짜가 없으면 파일명·내용에서 추정하고 "추정"이라고 표기한다.

### 2. source 요약 생성
- `wiki/sources/<원본과 같은 파일명>.md` 생성. 필수 섹션:
  - 원본 경로, 날짜, 유형
  - 요약 (5줄 이내)
  - 핵심 수치·조건 (사실 — 원본에 있는 것만, 그대로 옮긴다)
  - 해석 / 가설 / 미확인 (해당 시)
  - 연결: 관련 wiki 페이지 링크

### 3. 관련 페이지 갱신
- concepts/: 재사용될 개념·수치가 있으면 해당 페이지 갱신 또는 신규 생성
  - 재사용 수치의 상세(값·기준일·충돌 이력)는 **concepts 한 곳에만** 둔다. 다른 페이지에서는 값을 다시 쓰지 말고 링크로 참조 (여러 곳에 복사하면 갱신 시 어긋남)
  - 예정·일정은 원본에 날짜가 있을 때만 날짜로 쓴다. 원본이 "분기마다"처럼 상대 표현이면 그대로 옮기고, 날짜를 도출했다면 "추론" 표기
- projects/: 해당 프로젝트 페이지의 이력에 1줄 추가
- decisions/: 원본에 결정이 담겨 있으면 결정 문서 생성
  (형식: 날짜 / 상태 / 배경 / 선택지 / 결정 / 근거 / 롤백 방법)
- errors/: 오류·실패 사례면 오류 문서 생성
  (형식: 발생일 / 증상 / 원인 / 조치 / 재발 방지 규칙)

### 4. 충돌 검사
- 새 수치·조건이 기존 wiki 페이지와 다르면 CLAUDE.md의 충돌 처리 절차를 따른다:
  덮어쓰지 말고 `## 충돌 기록` 섹션과 index.md 충돌 현황에 기록.

### 5. index.md / log.md 갱신
- index.md: 새 페이지를 목차에 추가, 충돌 현황 갱신
- log.md: 맨 위에 `YYYY-MM-DD | ingest | 원본파일명 | 생성·갱신된 페이지` 1줄 추가

### 6. 자가 점검 (보고 전 필수)

2026-07-05 초기 검증에서 두 결함(무출처 수치, 끊어진 링크) 모두 이 단계 부재로 발생. 반드시 수행:

- [ ] 이번에 쓴 **모든 수치·조건이 원본에 실재하는지** 원본을 다시 열어 대조한다 (기억으로 쓴 내용 금지)
- [ ] 이번에 추가한 **모든 링크가 실제 존재하는 파일**을 가리키는지 확인한다 (index.md 포함)

## 금지

- 자동 삭제, 기존 페이지 자동 덮어쓰기(충돌 절차 없이), 외부 업로드·발송
- 원본에 없는 수치·조건을 요약에 추가하는 것
- 여러 파일 일괄 처리 (사용자가 명시적으로 순서대로 요청한 경우는 1개씩 반복)
