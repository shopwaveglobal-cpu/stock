# personal-llm-wiki — 운영 규칙

이 폴더는 개인 LLM Wiki의 루트다.
목적은 자료 보관이 아니라, 자료와 프로젝트 경험이 쌓일수록
**연결·결정·실패 사례가 누적되는 지식 시스템**을 유지하는 것이다.
이 규칙은 어떤 LLM 모델이 운영하더라도 동일하게 적용된다.

## 폴더별 책임

| 폴더 | 책임 | 수정 규칙 |
|---|---|---|
| raw/inbox/ | 처리 대기 중인 새 원본 | 파일 추가만. 내용 수정 금지 |
| raw/samples/ | 테스트용 원본 | 수정 금지 |
| wiki/sources/ | 원본 1개당 요약 페이지 1개 | 원본 재확인 후에만 갱신 |
| wiki/projects/ | 프로젝트별 현황·이력 | ingest 시 갱신 |
| wiki/concepts/ | 재사용되는 개념·정의·수치 | ingest 시 갱신 |
| wiki/decisions/ | 결정 기록 (1결정 = 1파일) | 추가만. 번복은 새 문서로 만들고 서로 링크 |
| wiki/errors/ | 오류·실패 사례와 재발 방지책 | 재발 시 같은 파일에 이력 추가 |
| wiki/syntheses/ | 재사용 가치가 있는 질의 결과 | 사용자가 저장에 동의한 것만 |
| wiki/index.md | 전체 목차 + 충돌 현황판 | 모든 ingest 후 갱신 |
| wiki/log.md | 작업 이력 (최신이 위) | 모든 ingest 후 추가 |
| tests/ | 평가 케이스와 실행 결과 | 평가 실행 후 갱신 |

## 절대 규칙

1. **raw/ 원본은 절대 수정·삭제하지 않는다.** 잘못된 원본이면 wiki 쪽에 "원본 오류 의심"으로 기록한다.
2. **wiki/의 모든 핵심 주장에는 출처를 적는다.** 형식: `(출처: raw/samples/파일명.md)` 또는 URL. 출처를 못 찾으면 그 주장은 쓰지 않는다.
3. **수치·날짜·일정·계산 결과는 답변 전에 raw 원본에서 재확인한다.** wiki 요약만 믿지 않는다.
4. **외부 수치(API 한도, 가격 등)는 기준일을 함께 적는다.** 형식: `(기준일: YYYY-MM-DD)`.
5. **사실 / 해석 / 가설 / 미확인을 구분해 표기한다.** 섞어 쓰지 않는다.
   - 사실: 원본·코드·공식 문서에서 직접 확인
   - 해석: 사실에서 논리적으로 도출 ("~로 보인다")
   - 가설: 검증 안 된 추측 (반드시 "가설:" 접두어)
   - 미확인: 원본에 없어서 알 수 없는 것 ("기록 없음")
6. **wiki에 없는 수치·조건을 임의로 만들지 않는다.** 없으면 "기록 없음"이라고 답하고 확인 방법을 제시한다.

## 충돌 처리

새 자료가 기존 wiki 내용과 다르면:

1. 조용히 덮어쓰지 않는다.
2. 해당 페이지에 `## 충돌 기록` 섹션으로 두 값·두 출처·날짜를 나란히 적는다.
3. index.md의 `충돌 현황` 표에 한 줄 추가한다. 상태: `미해결` / `해결(최신값 채택)` / `해결(원본 오류)`.
4. 날짜가 더 최신인 원본이 있으면 "최신값"으로 표시하되, 이전 값도 지우지 않는다.

## 저장 기준 (syntheses/)

- 저장하는 것: 여러 원본을 종합한 계산, 반복 참조될 비교표, 실행 계획.
- 저장하지 않는 것: 단순 검색 결과, 한 페이지만 다시 읽으면 되는 답.
- 질의 응답 후 자동 저장하지 않는다. 저장 가치가 있으면 사용자에게 제안만 한다.

## ingest 후 필수 갱신

모든 인입 작업이 끝나면 반드시:
1. wiki/index.md 목차·충돌 현황 갱신
2. wiki/log.md 맨 위에 작업 기록 1줄 추가
3. 변경 파일 + 새 충돌을 표로 보고

## 금지 사항

- 자동 삭제, 자동 덮어쓰기, 외부 서비스 업로드(발송 포함)
- API 키·토큰·비밀번호·회사 기밀이 든 자료의 인입
- **내부 전용(외부 공유 금지) 표시가 있는 원본의 git 커밋** — 이 저장소의 원격(GitHub)은 공개다. .gitignore에 등재하고 로컬에만 둔다
- 자료 100개 이상 일괄 인입 (한 번에 1개가 원칙)
- 벡터 DB, RAG 파이프라인 등 이 구조 밖의 복잡도 추가

## Skill

- 새 자료 인입 → `.claude/skills/wiki-ingest/SKILL.md`
- 질의 응답 → `.claude/skills/wiki-query/SKILL.md`
- 상태 점검 → `.claude/skills/wiki-lint/SKILL.md`

Skill 절차와 이 파일이 충돌하면 이 파일이 우선한다.
